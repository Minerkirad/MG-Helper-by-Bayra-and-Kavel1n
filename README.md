# MG Helper

**by Bayra & Kavel1n** · [Последняя версия](https://github.com/Minerkirad/MG-Helper-by-Bayra-and-Kavel1n/releases/latest)

## Быстрый старт

1. Скачайте `MG-Helper-Setup-*.exe` со страницы [релизов](https://github.com/Minerkirad/MG-Helper-by-Bayra-and-Kavel1n/releases).
2. Запустите установщик — права администратора не нужны (установка в профиль пользователя).
   SmartScreen может предупредить: приложение подписано, но самоподписанным сертификатом, пока не куплен доверенный — подробности в [docs/SIGNING.md](docs/SIGNING.md).
3. Приложение появится в трее и в автозагрузке; настройки игры продолжат охраняться автоматически.

Портативный вариант — ZIP из того же релиза: распакуйте и запустите `MGHelper.exe`.
Нужен Windows 10/11 x64 и PowerShell 5.1; WebView2 Runtime есть в системе по умолчанию
(если его нет, приложение откроется в упрощённом режиме — защита работает и так).

Проверка «всё ли цело» на своей машине: пункт **Диагностика** в приложении или
`diagnose.ps1` в папке `%LOCALAPPDATA%\MG_Helper`; отчёт можно отправить разработчику
одной кнопкой.

Хелпер для GTA V + Majestic RP + Miami Graphics. Не даёт Majestic затирать настройки графики игры, сохраняет json-конфиги Miami Graphics в снапшоты и возвращает ванильные `.bin` лаунчеру после игры.

## Как работает

| Когда | Что происходит |
|---|---|
| Запуск лаунчера Majestic | Если в папке лаунчера нет ванильных `.bin` — они докопируются из архива (страховка от ошибки 1002) |
| Запуск GTA 5 | Применяется твой эталон `settings.xml`; json-конфиги Miami Graphics сохраняются в снапшот (5 последних поколений) |
| Вся игровая сессия | Если настройки перезапишет лаунчер, они откатываются к эталону. По умолчанию охрана идёт всю сессию, а не первые 2 минуты |
| Выход из игры | Эталон возвращается на диск. Изменения, сделанные в игре, становятся новым эталоном только если в `config.json` включён `"allowAdopt": true` |

Политика по умолчанию — как в самой первой версии: что бы ни записалось в `settings.xml` во время игры, при выходе на диске снова эталон. Никакая чужая перезапись не может «усыновиться» молча.

## Эталон, adopt и охрана (3.0.0)

| Ключ `config.json` | По умолчанию | Смысл |
|---|---|---|
| `allowAdopt` | `false` | **единственный** включатель adopt. `true` — правки, сделанные в игре, при выходе становятся новым эталоном. `false` — эталон восстанавливается |
| `onExit` | `'restore'` | **устарел**, adopt больше не включает. Если там осталось `'adopt'`, watcher пишет в `watcher.log`, что ключ устарел и нужен `allowAdopt` |
| `sessionGuard` | `true` | kill-switch внутрисессионной охраны: `false` — чужие перезаписи не откатываются |
| `guardWindowSec` | `0` | `0` — охранять **всю** сессию; `>0` — только первые N секунд после обнаружения игры (старое поведение) |
| `coreMode` | `'ps'` | `'csharp'` — beta C#-ядро (`MGCore.cs`), выбирается установщиком; по умолчанию PowerShell-watcher |

Adopt срабатывает только когда эталон был применён нами в этой же сессии **и** файл изменился после нашей записи (сравнение времени — в UTC). Файл, который изменился до нашего применения, эталоном не станет.

Существующий `config.json` править не нужно: если `allowAdopt` в нём нет, после обновления поведение само становится как в v1. Старые значения `onExit: "adopt"` и `guardWindowSec: 120`, записанные установщиком 2.5/2.6, один раз мигрируются в новую политику (метка `cfgVersion`).

## Иконка в трее

Статус берётся только из `watcher.health.json` (свежесть heartbeat), а не из наличия `watcher.ready`.

| Иконка | Состояние | Условие |
|---|---|---|
| зелёная | Healthy | `status=running`, heartbeat свежий (≤ 15 с) |
| жёлтая | Degraded | heartbeat 15–30 с или watcher ещё стартует |
| красная / серая | Stopped | `status=stopping`, heartbeat старше 30 с, либо health-файла нет |
| жёлтая | Unknown | health-файл битый или нечитаемый |

Отдельно, даже при свежем heartbeat: `phase=UnknownSession` или несовпадение ключа эталона (сменилась игра/GPU) → жёлтая иконка «SAFE MODE: защита выключена». Переход в «не защищаю» всегда виден: событие в `events.jsonl` + статус в трее.

## Установка

1. Один раз запусти Majestic и зайди в GTA V
2. Скачай ZIP из [Releases](https://github.com/Minerkirad/MG-Helper-by-Bayra-and-Kavel1n/releases), распакуй
3. Запусти **MG-Helper.bat** → пункт **[1] Установка**

При первом запуске меню само предложит мастер установки.

## Меню

| Пункт | Что делает |
|---|---|
| [1] Установка | Ставит watcher (фоновая защита) + иконку в трее |
| [2] Reset settings | Текущие настройки игры становятся эталоном; показывает, что изменится |
| [3] Import settings | Импорт готового settings.xml с этого же ПК |
| [4] MAX FPS / [5] Отключить тени | Готовые профили, с диффом и подтверждением перед применением |
| [6] Очистка кэша | Очистка кэша Majestic (перекачка кэша при след. запуске) |
| [7] Восстановить MG | Вернуть json-конфиги Miami Graphics из снапшота (выбор поколения) |
| [8] Диагностика | Отчёт `report_*.txt` с кодами ошибок; твои пути маскируются по умолчанию |
| [9] Repair | Починить типовые проблемы |
| [11] Новый эталон | После смены видеокарты или обновления игры |
| [12] Обновления | Скачает релиз, проверит SHA256, установит |
| [13] История эталона | Вернуть прошлую версию эталона (undo) |
| [14]/[15] Свой профиль | Применить / сохранить именованный профиль настроек |

## Если что-то не работает

**MG-Helper.bat → [8] Диагностика**. Она создаст `report_*.txt` с кодами ошибок `MG-E-XXXX` — пришли файл автору. Расшифровка кодов и что означает SAFE MODE: [docs/errors.md](docs/errors.md).

## Детали

- Настройки у каждого свои — чужой settings.xml пакет не переносит (проверка видеокарты при импорте)
- Эталон применяется целиком: сменил монитор/разрешение вне игры — сделай [2] Reset settings, иначе вернутся прежние. Блок видеокарты профилями не редактируется
- Состояние watcher'а лежит в `%LOCALAPPDATA%\MG_Helper\watcher.health.json`: `status`, `phase`, `gamePid`, `lastHeartbeatUtc`, `sequence`. Файл обновляется каждые 5 с; по нему трей и диагностика отличают живого watcher'а от мёртвого. `watcher.ready` — только маркер готовности для установщика, доказательством жизни он не является
- Диск: хранит 2 поколения ванильных `.bin` (до ~4 ГБ в `%LOCALAPPDATA%\MG_Helper`), 5 поколений снапшотов json-конфигов MG и 10 бэкапов эталона — старое удаляет сам
- После правки `config.json` перезапуск watcher'а не нужен — он перечитывает конфиг раз в 30 минут
- Скрытые процессы: watcher и иконка трея не показывают окон, всплывающие уведомления о событиях — из трея
- Чего пакет не делает: он не прячет настройки Miami Graphics от лаунчера механизмом v1 (перемещением `*.bin`). Защита MG в 2.6.x — это снапшот json-конфигов и восстановление из него (пункт [7]); `.bin`-архив нужен только чтобы Majestic не упал с ошибкой 1002

Ручки config.json (`allowAdopt`, `onExit`, `sessionGuard`, `guardWindowSec`, `coreMode`) — см. [docs/architecture.md](docs/architecture.md).

- **Дисклеймер**: пакет не связан с Majestic RP и Miami Graphics. Использование на свой риск — правила лаунчеров могут меняться

## Отчёты в Telegram (опция)

Отчёт диагностики можно отправить разработчику прямо из меню [8]: если отправка
настроена, отчёт уходит в Telegram автоматически; вручную — `diagnose.ps1 -Send`.

Как включить (токен **никогда** не хранится в репозитории):

- переменные окружения `MG_TG_TOKEN` и `MG_TG_CHAT`, или
- файл `%LOCALAPPDATA%\MG_Helper\telegram.json`:
  `{"token":"123456:ABC...","chatId":"123456789"}`.

Чтобы отправка шла сама после каждого отчёта, добавьте в `config.json`
`"autoSendReports": true` (по умолчанию выключено: отправка — это ваше решение).
Без настроек отправка молча не выполняется, отчёт остаётся в папке watcher'а.
