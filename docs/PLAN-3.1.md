# План 3.1: MG Helper как приложение (exe, UI, иконка, авто-отчёты)

Документ описывает переход от «PS-меню + трей» к цельному десктопному приложению:
один установщик-EXE, современный интерфейс, своя иконка, автоотправка отчётов и
вылизанный основной функционал. План опирается на фактическое состояние репозитория
(3.0.0) и на то, что реально есть на машинах, а не на пожелания.

## 1. Что есть сейчас (факты)

- **Ядро**: `MgCore.dll`/`MgCore.exe` (чистые решения, parity 21/21 с PS-эталоном).
- **Watcher**: `MGHelper.Watcher.exe` (C#, net48), Named Pipe `\\.\pipe\MG_Helper`.
- **UI**: трей `MG-Helper-Tray.exe` (WinForms, 4 состояния, баллуны) + консольное меню
  `MG-Helper.ps1` (пункты 1–15 через `MG-Helper.bat`). Окна и дизайна нет.
- **Иконка**: рисуется кодом (четыре цветных круга), файлов иконки в репозитории нет.
- **Установка**: `install-3.0.ps1` (PS 5.1) + `App\Versions\<ver>\` + `current.json`,
  откат `-Rollback`; exe собираются `Add-Type` **на машине пользователя**.
- **Релиз**: ZIP + SHA256, автообновление через `update-helper.ps1` (PS).
- **Тесты**: `tools\check.ps1` — 111 проверок (контракты, parity обеих реализаций,
  интеграционные сессии PS и C# watcher'а, миграция, telegram-отправка), CI зелёный.
- **Машина разработчика**: .NET Framework 4.8.1 есть; **.NET SDK нет** (только рантаймы
  6/8); WebView2 Runtime **есть** (158.x); Inno Setup/ImageMagick нет; Pillow есть.
- Пакет сейчас весит ~670 КБ и не требует прав администратора.

## 2. Цель 3.1

1. **Один exe-продукт**: пользователь скачивает `MG-Helper-Setup-3.1.0.exe`, ставит,
   получает `MGHelper.exe` в меню «Пуск» и в трее — без консольных окон и без
   PowerShell-команд на главном пути.
2. **Красивый интерфейс**: одно окно с навигацией, тёмная/светлая тема, живой статус
   защиты, действия в один клик; трей остаётся, но становится частью приложения.
3. **Своя иконка**: осмысленный знак (щит/диск/настройки GTA), мультиразмерный `.ico`,
   состояния трея (защищено/внимание/выключено/неизвестно) в едином стиле.
4. **Автоотправка отчётов**: при ошибке/падении и по кнопке — отчёт уходит разработчику
   в Telegram, без утечки чужих данных и без токена в публичном пакете.
5. **Отполированный основной функционал**: статус, новый эталон, сброс, диагностика,
   восстановление MG, профили, обновление/откат, автозапуск — всё из UI, с понятными
   ошибками; PS-скрипты остаются «под капотом» как аварийный путь.
6. Ничего из инвариантов 2.6.1/3.0 не ломаем: эталон восстанавливается при выходе,
   adopt opt-in, охрана всю сессию, SAFE MODE виден, данные не перемещаются.

Не входит: кроссплатформенность, новые игровые фичи, переписывание C#-ядра.

## 3. Ключевые решения (ПРИНЯТЫ 2026-11-27)

| # | Вопрос | Варианты | Рекомендация |
|---|---|---|---|
| D1 | Стек UI | **ВЫБРАНО: C — WebView2 + HTML/CSS.** Хост `MGHelper.exe` (net48 WinForms + WebView2), интерфейс в `ui\` |
| D2 | Сборка exe | собирать на машине пользователя (`Add-Type`) или в CI и класть бинарники в релиз | **CI**: релиз содержит готовые exe + манифест SHA256; установка перестаёт компилировать что-либо |
| D3 | Установщик | **ВЫБРАНО: Inno Setup** (`Setup.exe`, CI ставит через choco) |
| D4 | Подпись кода | нет / self-signed / платный сертификат | Начать с «нет», заложить шаг подписи (SmartScreen будет ругаться — предупредить в инструкции). Self-signed хуже: всё равно предупреждение |
| D5 | Доставка отчётов | **ВЫБРАНО: релей (Cloudflare Worker)**; в пакете только публичный URL |
| D6 | Бренд | **РЕШАЕТ ЛИД:** знак «щит», акцент `#3BA55D`, тёмная тема по умолчанию; варианты иконки — на скриншотах |

## 4. Целевая архитектура

```
%LOCALAPPDATA%\MG_Helper\                 DataRoot (не меняется, совместимость)
  App\Versions\<ver>\                     InstallRoot: MGHelper.exe, MGHelper.Watcher.exe,
    current.json                          MgCore.dll, WebView2Loader.dll, ui\ (html/css/js), скрипты
  config.json, settings.golden.xml, …     данные пользователя

Процессы:
  MGHelper.exe          UI + трей + клиент Named Pipe (единственный видимый процесс)
  MGHelper.Watcher.exe  защита (уже есть, C#), поднимается задачей/приложением
  pipes:  \\.\pipe\MG_Helper              статус/команды (есть), + подписка на события

Поток данных: watcher пишет health/state/events → приложение читает через pipe
(файлы — резервный путь) → UI показывает живой статус ≤1 с.
```

Правило: **UI ничего не решает сам** — только читает состояние и отправляет команды
через pipe/скрипты. Логика остаётся в ядре и watcher'е (это же гарантирует parity).

## 5. Иконка и дизайн-система

1. `assets\icon.svg` — мастер-знак (единый стиль: щит, диск/шестерёнка, буквы «MG»).
2. `tools\make-icon.ps1` (Pillow) генерирует `assets\mghelper.ico` (16/20/24/32/48/64/
   128/256) и `tray-*.ico` для четырёх состояний (щит зелёный/жёлтый/серый/красный с
   бейджем), кладёт их в `ui\assets\`. Иконка попадает: окно, трей, ярлык, установщик,
   exe-ресурс.
3. Дизайн-система в `ui\styles\`: токены (цвета, радиусы, тени, типографика Segoe UI
   Variable), компоненты (карточка статуса, кнопка, поле, список, тост, модалка),
   тёмная/светлая тема, размеры под DPI 100/125/150/200%.
4. Экраны: **Обзор** (статус, фаза, PID игры, эталон, последние события, быстрые
   действия), **Настройки** (adopt/охрана/автообновление/автозапуск/тема), **Отчёты**
   (создать/отправить/история, согласие), **Журнал** (events.jsonl и watcher.log с
   фильтрами), **Инструменты** (новый эталон, сброс, восстановление MG, профили,
   диагностика, откат версии), **О программе**.
5. Требования: клавиатурная навигация, фокус-рамки, контраст WCAG AA, отсутствие
   мигания консоли, один экземпляр приложения.

## 6. Автоотчёты в Telegram

- Кнопка «Отправить отчёт» + авто-отправка при `AppDomain.UnhandledException`,
  падении watcher'а (событие `error`/`apply.failed` подряд) или «SAFE MODE» дольше N мин.
- Первый запуск: экран согласия «отправлять отчёты автоматически?» (по умолчанию нет).
- Состав отчёта: версия, ОС/PS, health, state, config (пути маскируются), события,
  хвост логов, код ошибки. Никаких имён пользователей/серийников — фильтр в коде + тест.
- Доставка через релей (D5): `POST /report` с SHA256 и версией, релей пересылает файл в
  Telegram-чат разработчика. В приложении — только URL; токен бота живёт на релее.
- Очередь: если сети нет — отчёт лежит локально, отправляется при следующем старте,
  не чаще одного раза в сутки за одинаковый отпечаток.

## 7. Основной функционал: что полируем

| Сценарий | Сейчас | В 3.1 |
|---|---|---|
| Установка | PS-скрипт из ZIP | `Setup.exe`: проверка версии, остановка watcher'а, staged deploy, ярлыки, uninstall |
| Статус | health-файл + трей | живой статус по pipe ≤1 с, «что именно защищено» (эталон, сессия, rollback'и) |
| Новый эталон / сброс | пункт меню [11]/[2] | кнопка + подтверждение + дифф «было → станет» (уже есть `Show-SettingsDiff`) |
| Восстановление MG | пункт [7] | выбор поколения снапшота, предпросмотр файлов, бэкап перед записью |
| Профили | пункты [14]/[15] | список профилей, применение, создание из текущих настроек |
| Обновление | `update-helper.ps1` | проверка обновлений в UI, скачивание с проверкой SHA256/подписи, переключение версии, откат |
| Автозапуск/трей | ярлык + задача | переключатель в настройках, честное состояние (задача/ярлык/нет) |
| Ошибки | текст в консоли | человеческие сообщения + код (`MG-E-xxxx`) + кнопка «отправить отчёт» |

## 8. Этапы

### M1. Каркас приложения и сборка (S/M) — **каркас готов**
- Решение D1/D2/D3; `src\ui\` (хост-окно + WebView2) или WinForms-эквивалент.
- `MGHelper.exe --smoke` (открывает окно, пишет `ui-smoke.ok`, закрывается) для CI.
- Сборка exe в CI (артефакт), в релизе — готовые бинарники; `install-3.1.ps1`
  раскладывает их в `App\Versions\3.1.0` и переключает `current.json`.
- DoD: установка из ZIP на чистую машину, окно открывается, трей есть, `check.ps1` зелёный.

### M2. Дизайн и иконка (M)
- `assets\icon.svg` → `make-icon.ps1` → `mghelper.ico` + 4 состояния трея.
- Дизайн-токены, темы, компоненты; экраны «Обзор» и «Настройки» целиком.
- DoD: скриншоты всех экранов (тёмная/светлая, 100% и 150%), иконка в окне/трее/ярлыке.

### M3. Живой статус и действия (M)
- Pipe-клиент в приложении (status/stop/reload/apply + события), обновление раз в секунду.
- Действия: новый эталон, сброс, восстановление MG, профили, диагностика, перезапуск watcher.
- DoD: интерактивный прогон с песочным watcher'ом (как `tools\integration.ps1`), но через UI
  (автотест: smoke-режим с заранее поднятым sandbox-watcher'ом).

### M4. Отчёты и авто-отправка (M)
- Релей (Cloudflare Worker, отдельный репозиторий/файл), приложение шлёт multipart.
- Согласие, оффлайн-очередь, защита от спама, тест «ничего лишнего в отчёте».
- DoD: живая отправка в ваш Telegram-чат; отчёт с машины без сети уходит после
  восстановления связи; тест на утечку путей.

### M5. Установщик, подпись, обновление (M/L)
- Inno Setup: `Setup.exe` (ярлыки, uninstall, проверка версии, откат), CI собирает и
  кладёт в релиз вместе с ZIP.
- Обновление внутри приложения (проверка/скачивание/проверка хэша/применение/откат).
- DoD: установка → обновление 3.1.0 → 3.1.1 → откат на копии данных; uninstall не удаляет
  пользовательские файлы.

### M6. Полировка и релиз (M)
- Онбординг первого запуска, пустые состояния, тосты, локализация RU, горячие клавиши.
- Ручной чек-лист на чистой машине (сценарии из §7), CI зелёный, `parity`/`check` без регрессий.
- DoD: релиз 3.1.0 (тег, ZIP, Setup, SHA256, заметки), `current.json`-откат проверен.

## 9. Гейты качества (на каждом этапе)

1. `tools\check.ps1` — ALL GREEN (111+ и растёт только вместе с тестами).
2. `tools\parity.ps1 -Both` — 21/21, решения не менялись.
3. UI smoke в CI: `MGHelper.exe --smoke` возвращает 0 и не оставляет процессов.
4. Интеграция UI↔watcher на песочнице (`MG_HELPER_DIR`), живая установка не участвует.
5. Любой новый бинарник — с хэшем в манифесте и в теле релиза.
6. Никаких токенов/путей пользователя в репозитории и в отчётах (тест).

## 10. Риски и ответы

| Риск | Ответ |
|---|---|
| WebView2 отсутствует/сломан на машине | детект при старте → окно с инструкцией + fallback на WinForms-экран статуса |
| .NET SDK нет локально (есть только рантаймы) | сборка UI в CI; локально — `dotnet-install.ps1` или CodeDom-хост (если выбран WinForms) |
| Неподписанный Setup пугает SmartScreen | инструкция + шаг подписи в плане; релиз с SHA256 |
| Токен Telegram утечёт | только релей; токен живёт на сервере |
| UI начнёт «решать» за ядро | правило §4: только чтение статуса и команды |
| CI станет медленным | UI-сборка отдельным job, smoke ≤ 60 с |
| Объём работ расползётся | фиксируем scope 3.1 = UI+иконка+отчёты+полировка; новые фичи — 3.2 |
