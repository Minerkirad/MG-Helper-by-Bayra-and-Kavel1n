# ADR-005: PS-watcher остаётся на один релиз как legacy и удаляется по чек-листу

**Статус:** принято (план 3.0, этапы 5 и 7). Дата: 2026-11-27.

## Контекст

PS-watcher — единственная проверенная в бою реализация защиты: на нём выпущены
v1…2.6.1. C#-watcher появится на этапе 5, но «написано и проходит тесты» ≠ «можно
удалять». Удаление старого пути — точка невозврата: если новое ядро где-то ведёт себя
иначе, пользователь остаётся без защиты.

## Решение

- В релизе 3.0.0 оба пути существуют: `MGHelper.Watcher.exe` (новый, по умолчанию) и
  `gta-settings-watcher.ps1` (legacy, запускается флагом `-Legacy` или при отсутствии
  нового exe).
- Одновременно они не работают: общий mutex `Local\MG_Helper_Watcher`, второй
  экземпляр молча выходит (поведение сохранено).
- Удаление legacy — только после чек-листа §9 плана (`docs/PLAN-3.0.md`):
  parity ядра на `expected.json` (решения + события), зелёный `check.ps1` на чистом
  клоне, интеграционные тесты на все инварианты, миграция и откат, проверенные на
  копии `backups\2.6.1\`.

## Последствия

- Откат 3.0.0 → 2.6.1 возможен без переустановки: legacy-скрипт в поставке.
- Деплой на один релиз тяжелее на ~50 КБ скриптов — приемлемо.

## Откат

`config.json` → `watcher: "legacy"` (или запуск скрипта вручную из папки установки).
После удаления legacy (3.1) откат — только из резервной копии/тега v2.6.1.
