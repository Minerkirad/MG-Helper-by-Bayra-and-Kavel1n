# ADR-003: IPC через Named Pipe, файлы — резервный канал на один релиз

**Статус:** реализовано в 5a (сервер HelperPipe.cs + клиент Invoke-MgPipeCommand, файловый резерв сохранён). Дата: 2026-11-27.

## Контекст

Сейчас «IPC» — это файлы: трей опрашивает `watcher.health.json` и `events.jsonl`,
меню просит watcher остановиться именованным событием `Local\MG_Helper_Stop`. На живой
машине разработчика это событие **не открывалось** (`MG-E-0105`) — пришлось добавить
файловый флаг `stop.request`. Опрос файлов даёт задержку до 5 с и гонки на чтении во
время записи; команд «применить эталон сейчас» или «перечитать конфиг» нет вообще.

## Решение

Именованный канал `\\.\pipe\MG_Helper` (JSON-строки, по запросу на соединение):

| Запрос | Ответ |
|---|---|
| `{"cmd":"status"}` | `{schema:1, pid, status, phase, gamePid, lastHeartbeatUtc, sequence}` — то же, что health |
| `{"cmd":"stop"}` | `{"ok":true}` и кооперативная остановка |
| `{"cmd":"reload-config"}` | перечитать `config.json` без перезапуска |
| `{"cmd":"apply-golden"}` | применить эталон (пункты меню [2]/[11]) |

ACL канала — только текущий пользователь (SID из токена процесса), `PIPE_REJECT_REMOTE_CLIENTS`.
События по-прежнему **пишутся в `events.jsonl`** (контракт и диагностика), а трей
получает их либо опросом файла, либо подпиской на канал (реализация трея — ADR-004).

## Последствия

- Команды меню перестают зависеть от именованных событий и работают предсказуемо.
- Файловый путь (`health`, `stop.request`) сохраняется как резерв на один релиз:
  если канал недоступен, поведение 2.6.1 остаётся рабочим.
- Нужны тесты «два клиента», «клиент отвалился посреди записи», «канал занят».

## Откат

Трей и меню умеют обе схемы; отключение канала — флаг в конфиге (реализуется на
этапе 5) или отсутствие `MGHelper.Watcher.exe` (тогда работает PS-watcher).
