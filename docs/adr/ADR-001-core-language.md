# ADR-001: ядро решений на C# (net48), PowerShell остаётся для меню и диагностики

**Статус:** принято (план 3.0, этап 4). Дата: 2026-11-27.

## Контекст

Решения watcher'а (применять ли эталон, уходить ли в adopt, активна ли охрана,
какой файл считать эталоном) сейчас живут в `common.ps1` и `gta-settings-watcher.ps1`.
PS 5.1 — среда с поздним связыванием: ошибка в имени параметра или типе выясняется
в рантайме, а не при сборке; типы `[bool]`/`$null` в позиционных вызовах уже давали
реальные дефекты (adopt без apply, tri-state сравнение). Кроме того, PS-watcher
нельзя подписать, а его IPC — файлы.

## Решение

Чистые решения переносятся в C# (net48, компилируется тем же `Add-Type`, что host и
трей — новых зависимостей нет). PowerShell остаётся **оболочкой**: меню, диагностика,
одноразовые операции, установщик. Watcher на C# (этап 5) использует то же ядро.

Реализация: `CoreDecisions.cs` (класс решений + `--decide <request.json> <response.json>`) компилируется в `MgCore.exe` тем же `Add-Type`; `tools\parity.ps1 -Implementation core` гоняет его на том же `expected.json`, что и PS-эталон, и сравнивает фактическиt значения построчно (`-Both`).

Ключевой критерий: ядро — это **чистые функции** (входы → выходы), без обращения к
реестру и процессам; ввод-вывод остаётся у процесса-хоста.

## Последствия

- Решения получают компиляцию, типы и unit-тесты без PS-рантайма.
- Параллельно живёт PS-модуль (`MgHelper.Core.ps1`) — эталон поведения для parity;
  удаляется на этапе 5 после зелёного `-Implementation core`.
- Пользовательские скрипты не переписываются — они продолжают звать `common.ps1`.

## Откат

`config.json` → `coreMode: "powershell"` (ключ уже есть, используется beta-ядром).
Удаление ядра не затрагивает данные: состояние, эталон и журналы остаются файлами.
