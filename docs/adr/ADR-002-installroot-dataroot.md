# ADR-002: InstallRoot и DataRoot, данные остаются на месте

**Статус:** принято (план 3.0, этап 6). Дата: 2026-11-27.

## Контекст

Сейчас программа и данные лежат в одной папке `%LOCALAPPDATA%\MG_Helper`: туда же
деплоятся скрипты, там же `config.json`, эталон, история, `mg_snapshot` (мегабайты)
и `vanilla_backup_archive` (гигабайты). Обновление копирует файлы по одному в ту же
папку, откат версии означает переустановку, а сбой копирования оставляет смесь
версий. При этом пользовательские данные при обновлении не должны двигаться вообще.

## Решение

- **InstallRoot** = `%LOCALAPPDATA%\MG_Helper\App\`, внутри `Versions\<ver>\` и
  `current.json` (`{"version":"3.0.0","path":"Versions\\3.0.0"}`). Переключение
  версии — атомарная замена `current.json`, старые каталоги удаляются после успешного
  старта новой версии.
- **DataRoot** = `%LOCALAPPDATA%\MG_Helper` (**как сейчас**): config.json, state,
  events, эталон с историей, журналы, снапшоты, архив `.bin`. Миграция раскладки
  ничего не перемещает, только создаёт `App\` и переносит туда исполняемые файлы.

## Последствия

- Откат = переключение указателя, а не переустановка.
- Обновление перестаёт трогать пользовательские файлы; staged deploy остаётся, но
  теперь пишет в версионный каталог.
- Пути в `config.json` не меняются — старые скрипты и diagnose работают с тем же
  DataRoot.

## Откат

`current.json` можно вернуть на предыдущую версию одной командой. Если каталог `App\`
не создан (миграция не запускалась), поведение 2.6.1 сохраняется полностью.
