# Подпись кода в MG Helper

Коротко: **самоподписанный сертификат не убирает предупреждение Windows.** Он
доказывает целостность файла, но система не доверяет издателю, которого не знает.
Ниже — что именно нужно, чтобы установка проходила без «Windows защитила ваш ПК» и
без UAC, и как это включить, не меняя код.

## Что происходит при установке сейчас

| Этап | С self-signed | С настоящим сертификатом |
|---|---|---|
| Запуск `MG-Helper-Setup-*.exe` | SmartScreen: «Windows защитила ваш ПК» → «Подробнее» → «Выполнить всё равно» | Первый экран без предупреждения (EV — сразу, OV — после набора репутации) |
| Права | UAC **нет**: установка per-user в `%LOCALAPPDATA%\MG_Helper` (`PrivilegesRequired=lowest`) | так же, UAC нет |
| Проверка файла | подпись `Valid` там, где установлен наш `.cer` | `Valid` у всех пользователей |

Важно: **UAC-запрос мы не вызываем вообще** — установщик ставится в профиль
пользователя и не требует прав администратора. Остаётся только SmartScreen, и его
снимает исключительно доверенный издатель.

## Варианты сертификата (для России актуально)

| Вариант | Цена (ориентир) | SmartScreen | Требования |
|---|---|---|---|
| **EV code signing** | ~$300–600/год | Предупреждения нет сразу | Юрлицо/ИП, проверка, USB-токен или облачный HSM |
| **OV code signing** | ~$200–400/год | Предупреждение, пока не накопится репутация (недели/тысячи установок) | Юрлицо/ИП, проверка |
| **Azure Trusted Signing** | ~$10/мес | Как EV-подобная подпись, привязана к verified publisher | Аккаунт Azure + подтверждённая история организации (часто ≥3 лет) |
| **Self-signed (сейчас)** | 0 | Предупреждение всегда, кроме машин, где установлен наш `.cer` | — |

Для сравнения: с 2023 года обычные (не-EV) сертификаты обязаны хранить ключ в
аппаратном модуле, «просто PFX на диске» у новых сертификатов уже не бывает — но
наш пайплайн умеет и облачные ключи через signtool/Azure Trusted Signing, и PFX для
сертификатов, которые допускают экспорт ключа.

## Как включить настоящую подпись (без правок кода)

1. Получить сертификат (EV/OV) или настроить Azure Trusted Signing.
2. Положить PFX и задать пароль:
   - локально: `$env:MG_SIGN_PFX_PASSWORD = '<пароль>'`
   - в GitHub: секреты `SIGNING_PFX_BASE64` (файл PFX в base64) и `SIGNING_PFX_PASSWORD`.
3. Собрать релиз: `.\tools\package-release.ps1 -Upload` (с `-Pfx` берётся секрет).
   `tools\sign.ps1` подпишет `MgCore.exe`, `MGHelper.Watcher.exe`, `MGHelper.exe` и
   `MG-Helper-Setup-*.exe`, а `package-release.ps1` **откажется публиковать** артефакты,
   если хоть один файл не `Valid`.
4. Проверить: `Get-AuthenticodeSignature <файл> | Select Status, SignerCertificate`.

Для Azure Trusted Signing шаг подписи заменяется вызовом `trusted-signing-cli`
(или `signtool` с `/dlib` провайдером) — файлы и проверка те же.

## Что уже сделано в репозитории

- `tools\sign.ps1`: подпись SHA256 + метка времени RFC3161 (при недоступном сервере
  подписывает без неё и сообщает), режимы `-Pfx` и `-CreateSelfSigned -TrustLocal`,
  идемпотентное добавление публичного `.cer` в доверенные корни пользователя.
- `tools\package-release.ps1`: обязательная подпись всех exe, включая Setup; хэши
  SHA256 в `release\RELEASE-NOTES-<ver>.md`; публикация ассетов в GitHub Releases.
- `tools\check.ps1`: гейт «каждый собранный exe подписан и Valid» (115 проверок).
- `assets\certs\mghelper-selfsigned.cer`: публичная часть текущего self-signed
  сертификата (отпечаток `64C68FD883A71E39B4C7D2C0BEF1E58CECEDE31B`).
- `.gitignore`: `*.pfx`, `*.pvk` — закрытые ключи в репозиторий не попадают.

## Чего ждать пользователю сейчас

Установщик подписан нашим self-signed сертификатом. На чистой машине SmartScreen
покажет предупреждение — это ожидаемо и **не признак проблемы с файлом**; после
покупки сертификата предупреждение исчезнет без изменения кода. Инструкция для
пользователя живёт в `README.md` (раздел про установку).
