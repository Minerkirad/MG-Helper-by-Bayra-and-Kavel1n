# Security Policy

## Что делает пакет с привилегиями
- Всё выполняется от имени текущего пользователя, **без elevation**.
- Задача планировщика: Limited, интерактивная сессия.
- Установщик снимает Mark-of-the-Web со скриптов скачанного пакета и компилирует
  два неподписанных exe (`MG-Helper-Host.exe`, `MG-Helper-Tray.exe`) в
  `%LOCALAPPDATA%\MG_Helper` из читаемых `.cs`-исходников. Это осознанно:
  целостность проверяется smoke-запуском + `package_hashes.txt` (SHA256).

## Известный компромисс
- Папка установки user-writable: любой процесс от имени пользователя может
  подменить скрипты/exe. Для класса «тулза для игры без админа» это приемлемо;
  повышение привилегий не используется принципиально.
- `watcher.health.json` — обычный файл в user-writable папке, поэтому его можно
  подделать. Подделка меняет только то, что показывает иконка (статус
  Healthy/Degraded/Stopped/Unknown), и не включает и не выключает защиту: она
  живёт в самом watcher'е, а решение о записи эталона принимают его функции, а
  не читатели health-файла. Персональных путей в health-файле нет: только pid,
  версия, фаза, `gamePid` и время.

## Что НЕ делает пакет
- Не подключается к сети для исполнения кода (автообновление — opt-in, проверяет
  SHA256 из релиза, исполняет только верифицированный установщик).
- Не отправляет телеметрию. Не собирает пароли/токены.
- Не трогает файлы вне: settings.xml (чтение/запись графики), папки Majestic
  backup (возврат ванильных .bin), своей папки `%LOCALAPPDATA%\MG_Helper`.

## Как сообщить об уязвимости
- GitHub Issues с меткой `security` или приложением `report_*.txt`
  (из Диагностики — персональные пути маскируются по умолчанию).
